# GDD — 第一关：符文终点

**所属章节**：第一章  
**关卡编号**：1-1  
**核心机制**：基本翻滚、符文朝向、终点贴合  
**场景文件**：`Assets/Scenes/Chapter1/Chapter1_Scene1.unity`  
**状态**：重建基线

---

## 1. 概述

第一关教学基本翻滚和新的通关条件。玩家沿直线第一次抵达终点时，符文位于侧面，`SceneSwitcher` 拒绝启动；玩家退出终点，沿终点前方的方形调整回路滚动一圈，再次进入终点时符文面朝下，停留 2 秒后通关。

本关让玩家亲自经历一次完整的教学循环：

1. 到达终点；
2. 发现朝向错误；
3. 根据反馈继续探索；
4. 通过转向改变符文朝向；
5. 以正确姿态贴合终点。

全关保持平地，不加入高度差、升降机关、移动平台或推动方块。

## 2. 玩家感受

第一次抵达终点时，玩家会短暂产生“为什么没有通关”的疑问。终点立即给出明确但非惩罚性的朝向错误反馈，旁边可见的方形回路提示玩家还有可探索路线。玩家绕行后重新进入终点，看到符文与终点成功匹配，从而理解：

> 目标不是单纯抵达终点，而是把正确的面转到终点上。

期望情绪顺序为：

**操作确认 → 产生疑问 → 尝试修正 → 理解规则 → 成功确认**

## 3. 关卡布局

### 3.1 平面结构

```text
                  [□]—[□]
                   │     │
[出生]—[□]—[□]—[□]—[调整点]—[终点]
```

- 所有可行走格位于同一高度。
- 出生点到终点中心的净位移为 5 格。
- 终点位于道路末端，终点右侧没有可行走地块。
- 调整点位于终点左侧相邻格。
- 调整点和它左侧的主路线格共同构成方形回路的下边。
- 两个额外地块构成回路的上边，形成一个 `1 × 1` 格方形回路。
- 主路线和回路均为一格宽，形状和连接关系必须从默认镜头下清晰可读。

### 3.2 建议网格坐标

以终点中心为 `(0, 0)`，忽略统一的 Y 高度：

| 功能 | XZ 坐标 |
|------|---------|
| 出生点 | `(-5, 0)` |
| 主路线 | `(-4, 0)`、`(-3, 0)`、`(-2, 0)` |
| 调整点 | `(-1, 0)` |
| 终点 | `(0, 0)` |
| 回路上边 | `(-2, 1)`、`(-1, 1)` |

实际搭建可以整体旋转或平移，但格位之间的相对关系不得改变。

## 4. 详细规则

### 4.1 初始状态

- 玩家出生在主路线起点。
- 玩家初始旋转必须让符文面朝上。
- 玩家可以立即使用 WASD 或方向键开始移动。
- 终点从关卡开始时即处于可检测状态。

### 4.2 第一次错误到达

玩家沿主路线向终点方向连续滚动 5 格：

```text
右 → 右 → 右 → 右 → 右
```

符文初始朝上，经过 5 次同方向的 90° 翻滚后位于侧面，因此第一次进入终点时不满足通关条件。

错误朝向进入终点时：

- 不累计通关停留时间；
- 不加载下一场景；
- 终点播放一次明确的“不匹配”反馈；
- 不弹开玩家、不造成伤害，也不自动重置；
- 玩家可以原路离开并继续调整。

### 4.3 朝向修正

玩家从错误终点退出，并沿方形回路完成修正：

```text
左 → 上 → 左 → 下 → 右 → 右
```

其中：

1. 第一个“左”让玩家退出终点，回到调整点；
2. “上 → 左 → 下 → 右”让玩家绕方形回路一圈并返回调整点；
3. 最后一个“右”让玩家再次进入终点。

完成这条路线后，符文面朝下。

### 4.4 正确通关

玩家以符文面朝下的姿态进入终点后：

- 终点开始累计停留时间；
- 正确匹配反馈在停留期间持续增强；
- 玩家连续停留满 `requiredDwellSeconds` 后通关；
- 本关建议 `requiredDwellSeconds = 2f`；
- 通关后加载 `Chapter1_Scene2`；
- 玩家在计时完成前离开终点时，本次进度立即重置。

## 5. 教学与反馈要求

### 5.1 方块符文

- 符文必须与普通表面形成明显视觉差异。
- 默认镜头下，玩家在移动过程中应能持续判断符文位于顶面、侧面还是底面。
- 出生时应让玩家清楚看到符文位于顶面。

### 5.2 终点

- 终点表面应使用与玩家符文相同或明显相关的图形语言。
- 玩家应能直觉理解终点需要与符文表面进行匹配。
- 终点必须在道路视觉末端，不能看起来像普通的路过式检查点。

### 5.3 错误反馈

错误反馈需要表达“朝向不匹配”，而不是“终点损坏”或“需要等待更久”。

反馈至少包含一种明确的视觉变化；条件允许时可以叠加短促音效。反馈应在进入终点后立即发生，不应等待 2 秒。

### 5.4 正确反馈

- 符文面朝下进入终点时，玩家符文与终点产生匹配反馈。
- 2 秒停留过程需要有可读的充能或确认进度。
- 正确反馈必须与错误反馈有明显区别。
- 场景切换应发生在确认反馈完成之后。

## 6. 公式与标准解

```text
每格边长 = cubeHalfSize × 2 = 1 单位

第一次抵达步数 = 5
修正路线步数 = 6
标准解总步数 = 11

第一次抵达路线 = 右 × 5
修正路线 = 左 → 上 → 左 → 下 → 右 → 右
```

朝向验证：

```text
初始符文方向 = 上
同方向滚动 5 次后的符文方向 = 侧面
完成指定方形回路并重新进入终点后的符文方向 = 下
```

上述朝向结果必须在场景搭建完成后通过 Play Mode 实测确认。若场景整体旋转，操作方向可以同步旋转，但滚动序列的相对结构必须保持一致。

## 7. 边界情况

| 情况 | 处理方式 |
|------|----------|
| 玩家错误朝向进入终点并持续等待 | 不累计时间、不通关，立即播放不匹配反馈 |
| 玩家错误进入后原路返回出生点 | 允许；再次沿同一路线进入时仍为错误朝向 |
| 玩家先探索回路、再首次进入终点 | 允许；如果符文已经朝下，可以直接通关 |
| 玩家反方向绕回路 | 允许自由尝试，不保证一次绕行即可得到正确朝向 |
| 玩家正确进入后提前离开 | 终点充能取消，停留计时归零 |
| 玩家滚出平台 | 正常下落；跌破 `killPlaneY` 后回到出生点并恢复初始朝向 |
| 玩家快速连按 | `Player` 每次只处理一个滚动，多余输入不造成跳格或重叠 |
| 玩家反复进入终点 | 每次进入均按当前实时符文朝向重新判定 |

## 8. 依赖

- `Player.cs`
  - 基本网格滚动与输入处理；
  - `IsRuneFaceDown()` 符文朝向判定；
  - 跌落后的出生点复位和初始朝向恢复。
- `SceneSwitcher.cs`
  - 正确朝向的停留计时；
  - 离开终点后的计时重置；
  - 加载 `Chapter1_Scene2`。
- `mechanism-respawn.md`
  - 跌破 `killPlaneY` 后的玩家复位规则。

### 当前实现缺口

- `SceneSwitcher` 已能拒绝错误朝向，但尚未提供明确的不匹配反馈。
- `SceneSwitcher` 已有 2 秒停留计时，但尚未提供可读的充能进度反馈。
- 场景重建时需要确认符文视觉与 `runeLocalAxis` 一致。

## 9. 可调参数

| 参数 | 建议值 | 影响 |
|------|--------|------|
| 出生点到终点距离 | 5 格 | 保证第一次抵达时符文位于侧面 |
| 调整回路尺寸 | `1 × 1` 格 | 最小可读朝向修正回路 |
| `Player.rollDuration` | `0.25f` | 基础翻滚手感 |
| `SceneSwitcher.requiredDwellSeconds` | `2f` | 正确匹配的确认时长 |
| 错误反馈时长 | `0.25–0.5s` | 需要即时可读，但不能阻塞玩家操作 |
| `Player.killPlaneY` | 按场景高度校准 | 控制跌落后的复位时机 |

## 10. 验收标准

- [ ] 玩家出生时符文面朝上，符文清晰可见。
- [ ] 玩家每次按键只翻滚一格，动画流畅且没有跳格。
- [ ] 玩家沿主路线向终点方向滚动 5 格后，第一次进入终点时符文位于侧面。
- [ ] 错误朝向在终点停留超过 2 秒也不会通关。
- [ ] 错误朝向进入终点时立即获得明确且非惩罚性的反馈。
- [ ] 终点右侧没有可行走地块，视觉上是明确的道路终点。
- [ ] 调整回路位于终点之前，并能从默认镜头下清楚识别。
- [ ] 按“左、上、左、下、右、右”完成修正后，符文面朝下。
- [ ] 正确朝向进入终点时显示持续 2 秒的匹配或充能反馈。
- [ ] 正确停留满 2 秒后加载 `Chapter1_Scene2`。
- [ ] 正确进入后提前离开会立即重置通关进度。
- [ ] 玩家跌出平台后能恢复出生位置和初始朝向。
- [ ] 标准解总计 11 次滚动，不依赖物理下落或随机旋转。
- [ ] 关卡内没有高度差、升降机关、移动平台或推动方块。
