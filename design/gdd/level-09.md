# GDD — 第九关：箱子 + 隐藏按钮

**所属章节**：第一章
**核心机制**：推箱子（PushableBlock）、升降台（隐藏按钮触发）、下落
**场景文件**：`Assets/Scenes/Chapter1/Chapter1_Scene9.unity`（已搭建，本文档记录的是搭建后实机调整过的最终布局）

---

## 1. 概述

第九关是第一章的收尾关，把推箱子（第六、七关）和升降机关触发（第五、八关）两条已经教过的规则线收束成一个新组合：玩家不再像第五关那样靠移动平台运送箱子，而是直接推箱子前进；玩家把箱子沿通道推向一段矮墙围出的凹陷区域，找准唯一的开口把箱子推下去，箱子跌落后精确落在凹陷区底部的隐藏按钮上，触发桥面升起，玩家从桥上走到对面到达本章终点。凹陷区边缘特意做成矮墙（顶面只比通道地面高一点，够不上"墙"的高度但足以挡住直接走/推进去），玩家沿通道前进时能直接看过矮墙瞥见下方的按钮，把"跌落"从此前几关暗示的风险，重新定性为一次可以被计算、被利用的手段——呼应刚上线的 `killPlaneY` 复位机制（跌落不再是不可挽回的失误）。

> **搭建后修订**：初版设计里隐藏按钮缺口开在主通道的北墙上（悬空、无遮挡），实机搭建后发现玩家在正常视角下根本看不到缺口下方，"能瞥见"这个核心可玩性要求没有兑现。搭建者据此把整个凹陷区挪到了通道南侧、用矮墙代替悬空缺口做遮挡，本文档第 3/5/7/8 节已按最终布局改写，不再是最初的悬空缺口方案。

## 2. 玩家感受

核心情绪是"我算准了"而不是"箱子丢了"。前几关（尤其第五关的机关缩回、第八关的桥会回缩）教会玩家谨慎对待不可逆或有时限的机关状态；第九关反过来利用这种警惕心——玩家看到箱子即将滑向凹陷区时会本能紧张，但矮墙挡不住视线，玩家在箱子跌落前就能看过墙头瞥见下方的按钮，这一瞥把"箱子要掉下去了"的焦虑转化为"哦，这是故意设计的路线"的顿悟。跌落瞬间的明确反馈（音效/发光）进一步确认这次跌落是玩家读对了机关，而不是失误——是本章"翻滚+推箱+机关触发"三条线里，第一次让"失去控制的物理下落"本身成为解谜的正解手段，而非需要规避的意外。

## 3. 详细规则

**网格与朝向**：以 1 格 = 1 单位（对应 `cubeHalfSize=0.5` 的吸附网格），`x` 为东西向、`z` 为南北向。以下坐标是实机搭建后的实际数值。

**区域划分**（南→北，`z` 递增）：

1. **主推箱通道**（`z=-2`）：1 格宽，地面 `y=0`（贴 `CubicTerrain` 惯例，方块中心 `y=-0.5`）。出生点 `(0,-2)`，箱子初始位置 `(2,-2)`。通道东端在 `x=6` 处被一块墙块（`CubicTerrain` 叠在地面上，中心 `y=0.5`）封死，防止箱子/玩家被推入未搭建的区域——这块墙**不是**逼玩家转向的机关，纯粹是边界收口，箱子被顶到 `x=5` 也不影响解谜（见下）。
2. **隐藏按钮凹陷区**（`z=-3`，主通道南侧）：`x=0,1,2,3` 一排矮墙（`CubicTerrain`，中心 `y=0.25`，顶面 `y=0.25`——比正常地面高 0.25、但达不到"墙"的完整高度），挡住玩家/箱子从这几列直接进入凹陷区，但因为矮墙顶面只比通道地面高一点，玩家站在通道上能直接看过墙头看到凹陷区内部。`x=4` 处没有放任何地形（真正开放），是整排矮墙里唯一的缺口——箱子/玩家只有从这一列才能真正掉下去。`x=5` 处是完整的墙+地面（不可通行），`x=6` 处只铺了地面没加墙（可站立但无法从通道那侧进入，纯粹是凹陷区边界的收尾地块，不参与解谜）。
3. **隐藏按钮**：凹陷区底部 `(4, y顶≈-0.75, -3)` 是隐藏的 `ElevatorSwitch` 压力板（`holdDuration=0.4s`），箱子从 `x=4` 缺口跌落后精确落在上面。
4. **连接墙**（`z=-1`，分隔主通道 `z=-2` 与原主通道 `z=0`）：`x=0,2,3,5` 是墙，`x=1,4,6` 是开放连接格——玩家借这三处在两条通道间平移，不涉及任何高度变化（本关不使用攀爬，两条通道严格同高，顶面都是 `y=0`）。
5. **原主通道**（`z=0`）：地面 `x=0..6` 全通，两侧于 `z=1` 抬高（`x=0,1,2,3` 是墙，沿用第六关"抬高即视为墙"的规则）。这条通道上原本设计过一块挡路的大石头，实机搭建后已经拿掉——现在这条通道纯粹是"解完谜后走去桥那边"的通路，不参与推箱谜题。`z=1、x=4` 处北墙留了一个缺口（旧设计里悬空缺口的遗迹），缺口下方现在什么都没有，跌进去只会触发 `killPlaneY` 复位，不通向任何机关——保留作为一个无害的"好奇心陷阱"，和 `x=6` 的深渊同性质，不需要特殊处理。
6. **桥与终点**：`x=6` 处的 `Elevator`/桥被隐藏按钮触发后从 `z=1` 升到 `z=2`，玩家跨过深渊到达终点 `(6,3)`；`SceneSwitcher` 是项目自带的 `Assets/Prefabs/SceneSwitcher.prefab`，不是拿原始 Cube 拼的。

**解谜序列**：

1. 玩家在主通道（`z=-2`）把箱子从 `(2,-2)` 向东推；矮墙让玩家老远就能看到南边凹陷区里的按钮轮廓，意识到需要在某一列把箱子推下去。
2. 玩家把箱子推（或推过头后退回来）到 `(4,-2)`，走到箱子北侧的 `(4,-1)`。
3. 从 `(4,-1)` 向南推箱子，箱子从 `(4,-2)` 被推入 `(4,-3)`——这是矮墙缺口唯一能通过的一列，`PushableBlock.FallIfUnsupported()` 触发，箱子下落，落点精确对齐（网格保证 XZ 不偏移），压在隐藏按钮上。
4. `ElevatorSwitch` 检测到箱子（`CanActivate` 同时识别 `Player`/`PushableBlock`），`holdDuration`（0.4s）后触发目标 `Elevator`（桥）上升；箱子永久留在按钮上，因此按钮不会自动复位（见"可调参数"）。
5. 玩家经 `z=-1` 分隔墙上任一开放连接格（`x=1`/`x=4`/`x=6`）回到原主通道（`z=0`），一路向东走到 `(6,0)`（石头已拿掉，畅通无阻），跨过升起的桥 `(6,1)→(6,2)`，到达终点 `(6,3)`。

**这一版实际是怎么"不可绕过"的**：这一版**没有**东西向的硬性挡路机关强制玩家在 `x=4` 停手——箱子理论上可以被多推一格到 `x=5`（`x=6` 的墙块才是真正的推动上限）。但这不影响解谜完整性，因为矮墙缺口只在 `x=4` 这一列存在：不管箱子被推到 `x=4` 还是 `x=5`，玩家都必须先把它挪回 `x=4` 才能推得下去——多推一格只是可回退的多余步骤，不是死路，也不能靠它跳过推箱步骤。真正"不可绕过"的约束来自矮墙缺口的唯一性，而不是通道本身的东西向限位。

## 4. 公式

本关不引入新机制，不新增公式，复用以下已有机关公式（定义见对应文档，此处仅代入本关数值）：

```
推箱目标格 = SnapToGrid(当前位置 + 推动方向向量)          — mechanism-pushable-block.md §4
占位检测盒尺寸 = cubeHalfSize × 0.9（三轴）                 — mechanism-pushable-block.md §4
下落检测射线长度 = cubeHalfSize + 0.05f（向下）             — mechanism-pushable-block.md §4
```

本关唯一的场景专属推导是 `killPlaneY` 取值：

```
killPlaneY 建议值 = 场景最低有效地形 Y − 2~3 个单位         — mechanism-respawn.md §4
本关最低有效地形（搭建后实际值）= 隐藏按钮台面 Y ≈ -0.75
按公式重新推导 = -0.75 − 2~3 ≈ -2.75 ~ -3.75
```

> **搭建后修订**：凹陷区从最初设计的 3 格深（`y≈-3`）改浅到约 0.75 格深后，`killPlaneY` 理论上可以从当前实际值 `-6f` 收紧到 `-3` 左右——`-6f` 目前仍然安全（不会误判正常落地为跌出边界），只是比实际需要的深了一倍多，跌入 `x=6`/`(4,1)` 深渊后要多等一小段时间才触发复位。是否收紧留给后续手感调优，不是本次必须修的问题。

## 5. 边界情况

| 情况 | 处理方式 |
|------|----------|
| 玩家把箱子往 `x=6` 方向一路推到底 | 在 `x=6` 处被墙块 `IsOccupied` 挡住，推动失败，触发 `Player.ShakeFeedback()`；箱子停在 `x=5`，不影响解谜——玩家把箱子推回 `x=4` 再往南推即可，是可回退的多余步骤，不是死路 |
| 玩家试图在 `x=0,1,2,3` 列把箱子往南推入凹陷区 | 矮墙顶面 `y=0.25` 高于正常地面，`IsOccupied` 判定为占位（哪怕只抬高一点也算），推动失败；`x=4` 是矮墙唯一的缺口，是箱子能被推下去的唯一一列 |
| 玩家试图绕开箱子直接沿主通道（`z=-2`）走到箱子对面 | 不可能：主通道 1 格宽，箱子挡死了唯一可通行的路径，玩家只能推 |
| 箱子跌落后没有精确落在按钮上 | 按 `PushableBlock` 机制，推动动画结束后先吸附到网格目标格 `(4,-3)` 再判定支撑、触发下落，XZ 位置由网格保证不偏移；落地后物理沉降的抖动幅度需要在实机 Play Mode 验证，若沉降超出按钮判定范围需扩大按钮 trigger 尺寸 |
| 玩家自己滚进隐藏按钮凹陷区（好奇或不慎） | 凹陷区没有围栏，玩家可以直接从 `x=4` 缺口滚下去；`ElevatorSwitch.CanActivate` 同样识别 `Player`，滚下去也会触发桥升起；玩家此时身处无法攀爬返回的凹陷区，需要主动往开放边缘移动触发跌落，才能借 `killPlaneY` 复位回出生点——允许但非最优路径，不构成谜题破坏 |
| 玩家不慎跌入旧主通道 `z=1、x=4` 处的遗留缺口，或 `x=6` 处真正的桥下深渊（发生在解谜完成之前） | 两处都是预期内的无害陷阱：触发 `killPlaneY` 复位回到出生点，箱子/机关状态不受影响，可重新尝试；前者是旧设计的遗迹，特意保留作为一个"好奇心陷阱"，不通向任何机关 |
| 箱子落地后开关是否会复位 | 不会：箱子永久压在按钮上，无"离开"动作，桥对应 `Elevator.reset = false`，触发后保持在目标位置，不需要处理"桥又缩回"的情况（与第八关"玩家离开按钮桥缩回"不同，此处按钮设计成不可能被清空） |
| 连续快速推箱子两次 | 沿用 `PushableBlock` 既有行为：第一次动画未结束时 `isMoving = true`，第二次调用直接返回 `false`，不叠加动画 |

## 7. 可调参数

| 参数 | 所属组件 | 当前实际值 | 说明 |
|------|----------|--------|------|
| `killPlaneY` | Player（本场景实例） | `-6f` | 凹陷区改浅到 `y≈-0.75` 后，按公式重新推导只需要 `-3` 左右；`-6f` 仍然安全，只是偏保守，跌落后复位会多等一小段时间——可选的手感优化，非必须 |
| 隐藏按钮凹陷区深度 | 场景布局 | `y: 0 → -0.75`（约 0.75 格） | 比初版的 3 格浅很多——初版深度是为"悬空缺口"设计的，改成矮墙遮挡方案后不需要那么深，浅一点反而让跌落到触发的反馈更快 |
| 矮墙遮挡（原计划的"镂空墙"） | 场景布局 | 沿凹陷区北侧 `x=0,1,2,3` 铺一排顶面 `y=0.25` 的矮墙 | 实际实现比最初设想的"镂空/断裂岩层"更简单直接：矮墙够不上完全遮挡视线的高度，玩家在主通道上就能看过墙头看到下面的按钮；效果上达到了同样的"跌落前先窥见"目的 |
| `ElevatorSwitch.holdDuration` | ElevatorSwitch（隐藏按钮实例） | `0.4s`（默认 `1f`） | 本关箱子落地即永久占位，没有"误触发后又松开"的风险，用更快的节奏给正反馈 |
| `Elevator.reset`（桥） | Elevator（桥实例） | `false` | 桥升起后保持，不需要处理"箱子被移走后桥缩回"的情况（本关箱子无法被再次移动） |
| `Elevator.moveDuration`（桥） | Elevator（桥实例） | `1f` | 与前几关桥/升降台的节奏保持一致 |
| 主通道东端墙块（`x=6,z=-2`） | 场景布局 | 单侧封边，无对应西侧限位 | 只负责挡住箱子/玩家越出已搭建区域，不是逼玩家在 `x=4` 停手的机关——真正保证解谜不可绕过的是矮墙缺口只在 `x=4` 一列打开（见"详细规则"） |
| 矮墙缺口位置（`x=4`） | 场景布局 | 固定唯一开口，`x=0,1,2,3` 是墙、`x=5` 墙+地面完整封死 | 是本关"必须把箱子推到这一列才能过关"这一约束的物理落地，误加/误删开口都会让谜题可绕过或无法通关 |
| 旧主通道 `z=1,x=4` 遗留缺口 | 场景布局 | 保留，下方无地形 | 悬空缺口方案废弃后的遗迹，特意保留作为一个无害的"好奇心陷阱"（同 `x=6` 深渊性质），不需要额外处理 |

## 8. 验收标准

- [ ] 玩家能在主通道（`z=-2`）把箱子从 `(2,-2)` 一路向东推，推到 `x=5` 后第三次尝试向东推因 `x=6` 墙块占位而失败并触发抖动反馈；箱子停在 `x=4` 或 `x=5` 都不影响后续解谜
- [ ] 玩家尝试在 `x=0,1,2,3` 任一列把箱子推入南侧凹陷区，均因矮墙占位而推动失败；只有在 `x=4` 才能成功把箱子推下去
- [ ] 玩家站在主通道 `x=0..3` 任意位置，能透过矮墙头看到南侧凹陷区里的按钮轮廓，验证"跌落前先窥见"这一可玩性设计成立
- [ ] 从 `(4,-1)` 向南推箱子后，箱子从 `(4,-2)` 掉入凹陷区，最终静止位置落在隐藏按钮的触发范围内（不需要额外微调即可稳定触发）
- [ ] 箱子落地并触发 `ElevatorSwitch` 后，桥在 `holdDuration`（0.4s）内开始上升动画，并保持在目标位置不缩回
- [ ] 玩家从出生点 `(0,-2)` 到终点 `(6,3)` 的完整解谜路径（推箱 → 南推入凹陷区 → 经连接墙回到原主通道 → 走到桥边 → 过桥）可以一次通关，无需借助任何未设计的捷径
- [ ] 玩家尝试不推箱子、只靠连接墙的开放格（`x=1/4/6`）在两条通道间穿行，验证桥不会升起、无法通关
- [ ] 玩家故意滚入隐藏按钮凹陷区后，若移动到开放边缘，能在合理时间内触发 `killPlaneY` 复位回到出生点，不会卡死悬停
- [ ] 玩家不慎跌入旧主通道 `z=1,x=4` 的遗留缺口，或 `x=6` 处桥下深渊（箱子谜题解开前），均能正常触发 `killPlaneY` 复位，不影响箱子/机关已有状态
- [ ] 终点的 `SceneSwitcher` 使用的是 `Assets/Prefabs/SceneSwitcher.prefab`（白色材质），不是临时替代的默认灰色 Cube
