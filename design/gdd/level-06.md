## 1. 概述

第六关正式教学推箱。丘陵和抬高地形把道路收束成一条折线路径，两个箱子分别挡住
东西向的两段路。玩家每次只需从箱子后方推动一格，箱子便停入道路尽头的安全停车格，
玩家从箱子原位置转弯继续前进。

两个推动动作规则相同，但发生在不同高度视觉区域和不同转弯节点，用来建立
“站在正确一侧—推动—从原位置转向”的基础模型。

## 2. 玩家感受

玩家第一次正面接触箱子时，前方停车格和紧邻的转弯都清晰可见。推动成功后，箱子
不再挡路，玩家自然从它原来的位置转向。第二个箱子重复这一结构，让玩家确认刚学到
的规则，同时开始把推动动作纳入路线规划。

布局约束：

- `X` 格代表比道路至少高 `0.25` 的丘陵阻挡，不可攀爬。
- 第一段道路为 `(0,0) → (1,0) → (2,0)`，`lower_box` 挡在终点。
- `lower_box` 被向右推动后停在 `(3,0)`；`(4,0)` 的丘陵阻止继续误推。
- 玩家从箱子原位置 `(2,0)` 向上转入第二段道路。
- `upper_box` 被向右推动后停在 `(5,1)`；`(6,1)` 的丘陵阻止继续误推。
- 玩家从箱子原位置 `(4,1)` 向上进入 `5 × 3` 的终点草地区。
- `E` 位于终点草地区内部 `(6,3)`，周围保留自由调整空间。

## 4. 详细规则

### 4.1 推动记法

`PUSH(a,R)` 表示玩家向右完成一次正常翻滚，同时把箱子 `a` 向右滑动一格。该动作：

- 计入一次 `steps`；
- 玩家移动到箱子的原位置；
- 箱子移动到声明的停车格；
- 玩家符文按一次 `R` 正常旋转。

### 4.2 两次基础推动

标准解先执行 `R PUSH(a,R)`，把 `lower_box` 停入 `(3,0)`。玩家随后 `U R` 到达
`upper_box` 左侧，再执行 `PUSH(b,R)`。两个箱子都只需推动一次。

停车格后方的丘陵提供明确物理限位。玩家即使再次朝箱子方向输入，也只会得到阻挡
反馈，不会把箱子推入不可恢复区域。

### 4.3 终点调整

第二次推动后，玩家以 `U R U R` 进入终点区并抵达 `E`。该路线既复习连续转向，也
使最终符文面朝下。终点区允许其他更长调整路线。

推箱状态搜索已验证：

- 每次推动的目标格为空且有支撑；
- 两个停车格互不冲突；
- 标准解正好推动 `a`、`b` 各一次；
- 玩家所有九步均位于合法地形；
- 最终箱子位置分别为 `(3,0)`、`(5,1)`；
- 最终玩家位于 `E`，符文方向为 `DOWN`。

## 6. 边界情况

| 情况 | 处理方式 |
|------|----------|
| 玩家再次推动已停车的箱子 | 后方 `X` 格占位，推动失败并播放抖动 |
| 玩家尝试从侧面提前推动第一个箱子 | 到达侧面所需路径被箱子和丘陵隔断 |
| 玩家尝试从错误方向推动第二个箱子 | 错误站位在推动前不可达或被丘陵阻挡 |
| 玩家推动时连续输入 | `PushableBlock.isMoving` 阻止重叠推动 |
| 玩家错误朝向进入 `E` | 不通关，可在终点草地区调整 |
| 玩家滚出道路边缘 | 下落后通过 `killPlaneY` 复位，箱子保留当前场景状态 |

## 8. 可调参数

| 参数 | 建议值 | 影响 |
|------|--------|------|
| 丘陵阻挡高度差 | `+0.25` 至 `+0.75` | 物理上均阻挡，视觉上可形成起伏 |
| `PushableBlock.pushDuration` | `0.25f` | 与玩家翻滚同步 |
| 每个箱子推动次数 | 1 次 | 保持本关为基础教学 |
| 终点调整区 | `5 × 3` 格 | 容纳自由符文修正 |
